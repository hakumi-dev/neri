# Data contract reference

Contract executables use `scripts/neri.sh` or the installed `neri` compiler.
This reference maps the typed data API, generation, diagnostics and provider
boundaries to their executable contracts. Commands use the repository root.

## Generic data contracts

The executable `runtime-contract` covers the shared runtime surface:

- `Query<T>.where(labels filters: fields of T)` resolves only declared labels
  and preserves source order for predicates and parameters. Omitted filters,
  `false`, non-null nullable text and explicit `NULL` are distinct cases.
- `fields of T` exposes all public supported entity fields. Mapping membership
  is validated by `translateFields` and `translateQuotation`; an unmapped but
  statically valid field returns `QueryFailure.UnsupportedCapability` rather
  than promising translation at compile time.
- `matching(predicate: quote fn(T): Bool)` accepts the supported quotation
  tree and captures values once. Cross-entity predicates and unsupported
  quotation operations are rejected.
- `orderBy`, `orderByString` and `orderByBool` accept typed field quotations;
  `take` records the bound, which `compile()` validates.
- `select(query, codec, selector)` is the shared generic projection entry
  point. The query infers `T`; the scalar codec infers `R`. Scalar decoders
  reject missing columns, wrong kinds and invalid NULL values.
- `compile()` produces the explicit plan and validates its limit, selected
  columns and scalar metadata. `all(provider)` checks provider capability and
  executes the plan.
- Plans expose placeholders and separately typed parameters. Values are never
  interpolated into preview SQL.

The generated example runs with `model::Customer` and `model::Order`. Its
generated context contains `Query<model::Customer>` and `Query<model::Order>`,
mapping metadata, strict entity decoders, `snapshot_Entity` and `key_Entity`
functions, and the mapped `Customer.id` to `Order.customerId` dependent query.
It does not generate per-entity query, field or snapshot classes.

## Generation and source contracts

`data-generation-contracts` exercises the `tooling/data` project against the
mapping and entity source fixture. It verifies mapped member and scalar checks,
inherited fields with origins on their declaring class,
deterministic source output, input and output digests, content-addressed
publication, manifest replacement, output repair, selected-unit isolation,
foreign-file protection and UTF-16 semantic origin spans. Generated sources
are loaded as ordinary project sources; definitions and `neri/sourceOrigin`
resolve through the recorded manifest.

Navigation metadata validates paired public collection/reference fields with
their exact entity types and records their source origins. Focused loading and
generated SQLite contracts cover batched collection reads, inverse references,
tracked identity, and failure before navigation publication; see
[navigation loading](NAVIGATION-LOADING.md) for reproduction commands.

The [reference-loading contracts](REFERENCE-LOADING.md) add optional foreign
keys, dependent-root reads, partial inverse collections, null versus missing
principals, and shared/self-referencing identity. Generator contracts compile
both optional integer and string mappings and reject incompatible nullable
types. Generated graph-link methods support required and nullable integer/string
foreign keys; [relationship contracts](RELATIONSHIPS.md) verify writes and rollback.
They also cover explicit reassignment and optional unlinking, including an empty
transaction commit before saving, update-before-delete ordering, and retry after
outer transaction rollback. Fresh contexts verify stored foreign-key values.
[Graph savepoint recovery](SAVEPOINTS.md) adds preservation of earlier saves,
retry after a later graph failure, full native transaction abort, and recovery
of generated keys and local reassignment/unlink intent.
The [cascade contracts](CASCADES.md) check transitive registered-link removal,
shared dependents, restrict boundaries, atomic preflight, and real SQLite
foreign-key failures with retry and rollback.
[Required orphan checks](ORPHANS.md) extend that consumer with severing a
required link, retaining its principal, deleting descendants, and preserving
the removal intent through failed saves and outer rollback.
[Client nullification checks](CLIENT-NULL.md) exercise mixed delete/null paths,
surviving dependents, generated keys, and updates ordered before immediate
SQLite FK restrictions. Failure and rollback checks preserve local null intent.

The generated project has `entities`, `data` and `sample` units. The `data`
unit owns the generated manifest and `database.hk`; the default sample is
`generated-example/sample.hk`. These are manual source fixtures for the
current generator workflow, not a claim of an automatic generator pipeline for
arbitrary projects.

## Scale boundary

The `benchmarks/data` probe measures generated bytes, generic instances, and
diagnostics for a four-field workload. Its output depends on the current
generator and compiler; it must be rerun after generated declarations change.
The provider contracts validate bounded reads, synchronous streaming, and
resource cleanup. They do not measure throughput, process memory, or SQLite
working storage.

## Editor contracts

The language-service fixture covers generic member completion, label and value
completion, quotation-body members, resolved documentation, definitions and
negative diagnostics. Quick documentation exposes the specialized
`Query<model::Customer>.where(labels filters: (fields of model::Customer))`
signature and the source method documentation. Generic source bodies with ambiguous specializations
retain an empty hover rather than selecting an arbitrary concrete type.

CLI, LSP and retained sessions agree on these first diagnostics:

| Invalid case | Diagnostic |
| --- | --- |
| Integer value for a Bool field | NR112 |
| Unknown field label | NR278 |
| Quotation from another entity | NR112 |
| Invalid Bool operator | NR120 |
| Misspelled factory | NR110 |

[Aggregate contracts](AGGREGATES.md) cover composite and null grouping keys,
global empty/all-null input, source stage preservation, typed decoding, and
provider failure boundaries. SQLite verifies integer overflow, bound hostile
text, input exceeding 1000 rows, mapped-row distinct before aggregation, and
per-aggregate scalar DISTINCT/FILTER. Filter coverage includes independent
metrics in retained groups, all-null and duplicate inputs, source limits/offsets,
immutable reuse, and SQL parameter order before derived-source parameters.
Compilation contracts verify both SQLite and PostgreSQL SQL and bind order;
execution verification uses SQLite.

## Current limits

The repository has a SQLite provider and an in-memory contract provider. Both
implement the bounded typed-read contract. Generated contexts accept a borrowed
provider for parameterless read terminals and tracked changes. The query
vocabulary supports typed [inner/left equijoins and compositional scalar
projections](JOINS-AND-PROJECTIONS.md). [Synchronous streaming](STREAMING.md)
adds untracked entity, projection, and join visitors with cooperative cancellation
and SQLite deadlines. Unbounded streaming retains each source query's stages;
buffered reads continue to require an explicit bound.
Explicit typed [migrations and column
inspection](MIGRATIONS.md) are separate SQLite provider operations. Generated
relationships produce filtered dependent queries and opt-in batched collection
loading with inverse references. The context detects scalar
changes and saves inserts, updates, and deletes in an atomic batch.

SQLite adapter and generated context contracts live in `providers/sqlite` and
`provider-contract`. They use isolated files created through test fixtures or
the production migration API; the application adapter opens files read-only or
explicitly writable and can create a missing writable database.
The `persistence` integration unit verifies terminals, object projections,
tracking, mutations, rollback/retry, and conflicts across contexts.
Reproduction commands and the
verified source references are in [README.md](README.md) and
[PROVIDERS.md](PROVIDERS.md). Detailed query and mutation contracts are in
[QUERY-AND-CHANGES.md](QUERY-AND-CHANGES.md).

Quotation calls and custom overloaded operators, indexing, casts,
arithmetic and control-flow statements remain rejected with `NR276`. Buffered
reads require a limit from 1 through 1000. Streaming allows unbounded input;
explicit `take` retains that range. The manifest and origin schema
are Neri-specific and are independent of ECMA-426 source maps.

## Commands

Positive contracts and the scale probe:

```sh
scripts/neri.sh run --project tooling/data --unit generator -- \
  "$PWD/experiments/neri-data/generated-example/mapping.json"
scripts/neri.sh run --project experiments/neri-data/generated-example --unit sample
scripts/neri.sh run --project experiments/neri-data --unit runtime-contract
scripts/neri.sh run --project . --unit data-generation-contracts -- "$PWD"
scripts/neri.sh run --project . --unit generated-source-contracts -- "$PWD"
scripts/neri.sh run --project experiments/neri-data/verification --unit verification
scripts/neri.sh run --project benchmarks/data --unit benchmark -- \
  "$PWD" "$PWD/scripts/neri.sh"
```

The focused invalid fixtures should fail with diagnostics:

```sh
scripts/neri.sh check --project experiments/neri-data/verification --unit invalid-wrong-bool
scripts/neri.sh check --project experiments/neri-data/verification --unit invalid-cross-entity
scripts/neri.sh check --project experiments/neri-data/verification --unit invalid-illegal-op
scripts/neri.sh check --project experiments/neri-data/verification --unit invalid-typo
scripts/neri.sh check --project experiments/neri-data/verification --unit invalid-named-argument
```
